## 1. Цель работы

Освоить управление версиями в Git: создание репозитория, фиксацию изменений, работу с ветками, разрешение конфликтов слияния, просмотр истории, отмену коммитов и работу с GitHub.

## 2. Создание репозитория и первые коммиты

Для выполнения задания создан учебный репозиторий с документацией корпоративной системы. В корне находятся `README.md`, `architecture.md`, `api.md`, `auth.md`.

Последовательность команд для локального выполнения:

```bash
mkdir Алакберова
cd Алакберова
git init -b master
git add .
git commit -m "Initial commit"
# Изменение содержимого файлов
git add .
git commit -m "Update initial project documentation"
```

В удаленном репозитории начальный коммит: `c7fc653`. После добавления `architecture.md`: `3792922`.

## 3. Создание и изменение ветки 1

Создана ветка `branch1` на основе исходной версии основной ветки. В `architecture.md` добавлены и изменены строки, а предыдущие строки удалены. Добавлен файл `auth.md`.

```bash
git switch -c branch1
git add .
git commit -m "branch1: edit architecture and add notifications"
git add auth.md
git commit -m "branch1: add authentication module"
```

Коммиты GitHub: `694475c`, `6aa3d76`.

## 4. Изменения основной ветки

В GitHub основной веткой является `main`, соответствующая `master` из задания. В нее добавлен `api.md`, а в `architecture.md` изменены строки, которые ранее изменялись в `branch1`. Эти изменения вызвали конфликт при попытке слияния.

```bash
git switch main
git add .
git commit -m "main: update architecture and integration gateway"
git add api.md
git commit -m "main: add API documentation"
```

Коммиты: `de882a4`, `3efed8f`.

## 5. Слияние веток и разрешение конфликта

Обе ветки независимо изменили одни и те же строки файла `architecture.md`. При слиянии эти изменения нельзя было объединить автоматически без выбора итогового содержимого. Конфликт разрешен путем объединения подходящих изменений в одну версию файла.

```bash
git switch main
git merge branch1
# Вручную отредактировать конфликтующие строки architecture.md
git add architecture.md
git commit
```

В GitHub зафиксирован merge-коммит `c4b2322` с двумя родительскими коммитами: `3efed8f` и `6aa3d76`. В итоговом `architecture.md` описаны REST API, шлюз интеграции, база данных, сервис авторизации и модуль уведомлений.

## 6. Просмотр истории

```bash
git branch -a
git log --all --graph --oneline --decorate
git status
```

История содержит последовательные коммиты, две линии разработки и отдельный коммит слияния. Историю также можно открыть на GitHub во вкладке **Commits**.

## 7. Откат изменений в ветке 1

На ветке `branch1` отменено добавление модуля авторизации. Откат выполнен через создание обратного коммита без переписывания существующей истории.

```bash
git switch branch1
git revert 6aa3d76
git log --oneline -3
```

В GitHub создан обратный коммит `34043d0`, который удаляет изменения, внесенные коммитом `6aa3d76`. Основная ветка `main` сохранила результат ранее выполненного слияния.

**Адрес проекта:** https://github.com/rwter5eretrtyer-dot/project-sim

Для обмена изменениями используются команды:

```bash

git push -u origin main

git push origin main
git pull origin main
git log --all --graph --oneline
```

На GitHub опубликованы ветки, история и итоговые файлы. Демонстрация команд получения и отправки данных была дополнительно выполнена локально с помощью двух клонов учебного удаленного репозитория. Добавление реальных участников подгруппы и отправка коммитов из их личных аккаунтов не подтверждены, поэтому этот пункт нельзя считать полностью выполненным.
